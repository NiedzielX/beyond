# Beyond ML Pipeline Audit — 2026-10-09

## Executive conclusion

Beyond should **not** replace its historical model with CatBoost simply because CatBoost is a stronger general-purpose tabular framework. On the current Lech historical dataset, the CatBoost challenger did not beat the incumbent on the untouched holdout MAE/WAPE and introduced materially stronger underprediction bias.

The most important issue is elsewhere: the live forecast records currently identify the historical baseline as `lech_v13_early_seasonality`, while historical R&D had already progressed to a stronger, horizon-specific v1.7 baseline. The next engineering step is therefore to align the live pipeline with the frozen v1.7 historical/context layer and then quantify the incremental uplift from live ticket-inventory signals.

## 1. Current live evaluation is too small

The current Supabase live dataset has only three completed matches with both an actual attendance outcome and a usable P50 forecast. Those evaluable forecasts are from `beyond-forecast-v0.1`; v0.2/v0.3 do not yet have completed evaluable matches.

Therefore:

- current live ±5/±10/MAPE metrics are diagnostic only;
- they must not be presented as evidence of current v0.3 quality;
- headline accuracy must use one latest forecast per completed match, not weight a match more heavily because it has more stored forecast observations;
- all forecast observations can still be used for horizon-level analysis.

## 2. Historical modelling foundation is real

The historical Lech work is substantially larger than the live evaluation sample.

The original dataset contained roughly 257 historical rows / 256 modelling rows. The modelling work then evolved through multiple iterations:

- v1/v1.1 — baseline attendance model and cleaned historical dataset;
- v1.2 — seasonality / Europe / weather ablation;
- v1.3 — early-seasonality + table-importance study;
- v1.4 — multi-horizon work;
- v1.5 — error anatomy;
- v1.6.1 — model hardening;
- v1.7 — frozen horizon-specific historical/context baseline;
- v1.8 — league feature factory research.

## 3. No-leakage review

The historical sporting-context builder records league position, points, PPG and recent form before updating the current match result. Attendance rolling features are shifted to use only previously completed matches.

The v1.3 evaluation uses season walk-forward testing:

- development: 2022/23 and 2023/24;
- untouched holdout: 2024/25 and 2025/26;
- a model for a test season is trained only on matches before that season begins.

This is an acceptable foundation for challenger benchmarking.

## 4. Incumbent model

The v1.3 incumbent is a sklearn `GradientBoostingRegressor` trained on the residual around rolling-5 attendance, with:

- opponent identity;
- historical rolling attendance;
- seasonality;
- pre-match table / points / PPG / recent-form context;
- recency weighting.

This is a solid benchmark but the algorithm itself is not a defensible product moat.

## 5. CatBoost challenger v0.1

CatBoost was evaluated using the same walk-forward rows and the same untouched holdout.

Candidate selection was performed only on development seasons. The selected challenger was:

- features: early feature set;
- target: direct attendance;
- loss: MAE;
- depth: 3;
- iterations: 500;
- learning rate: 0.03;
- L2: 10.

### Untouched holdout — 32 matches

| Model | MAE | MAPE | WAPE | Bias | ±10% |
|---|---:|---:|---:|---:|---:|
| Rolling-5 | 7,287 | 26.83% | 24.00% | -1,223 | 25.0% |
| Opponent mean | 9,716 | 29.30% | 32.00% | -9,321 | 12.5% |
| Beyond GB v1.3 | **5,318** | **18.04%** | **17.52%** | -2,338 | 31.25% |
| CatBoost challenger | 5,918 | 18.33% | 19.49% | -4,867 | **37.5%** |

### Decision

**Do not promote CatBoost.**

It improves ±10% hit rate but worsens the more important holdout MAE/WAPE and nearly doubles the negative bias. This is not a robust replacement.

## 6. Stronger historical baseline already exists

Later Beyond research produced v1.7, a frozen horizon-specific baseline:

- T30: Ridge residual model around current-season average, frequency-gated opponent identity, online same-season bias correction and stadium-capacity cap;
- T7: Ridge residual model around current-season average, gated table context and capacity cap;
- the research decision was to stop broad historical feature expansion and move effort to live ticket-inventory trajectories.

This is strategically aligned with the current product direction.

Important: v1.7 must not be compared directly with v1.3/CatBoost numbers until the evaluation horizon protocol is aligned. T30/T7 and generic pre-match evaluation are different tasks.

## 7. Live layer is the differentiator

The live pipeline already stores proprietary signals such as:

- public inventory level / index;
- net inventory movement;
- 6h and 24h velocity;
- acceleration;
- sector-level movement;
- anomaly exclusions;
- signal readiness / data gaps;
- live adjustment to historical forecast.

These signals are much more strategically valuable than swapping one commodity tree algorithm for another.

## 8. Highest-priority gap

Current live forecast rows still identify the historical baseline as `lech_v13_early_seasonality`.

The source code that performs the final historical + live blend is not present in the active `NiedzielX/beyond` GitHub repository. The repository previously contained only a minimal README. The live demand SQL / old artifacts exist outside the active source repository.

Before further model iteration, the live forecast generator should be moved into version control and its historical baseline upgraded deliberately.

## 9. Next implementation sequence

### P0 — Version the live forecast engine

Move the code that creates `forecast_observations` and combines historical forecast + live correction into `NiedzielX/beyond`.

Required outputs for every run:

- model version;
- historical model version;
- live feature version;
- correction version;
- source snapshot ID/time;
- P10/P50/P90;
- signal readiness;
- no-leakage / data-quality metadata.

### P1 — Promote historical v1.7 into the live architecture

Do not delete v1.3. Run v1.7 as a challenger/shadow baseline first and compare both on future completed matches.

### P1 — Make uplift measurable

Persist three point forecasts separately:

1. `historical_p50`
2. `live_adjustment`
3. `final_p50`

Evaluation must report:

- historical baseline error;
- final Beyond error;
- live correction uplift/degradation;
- uplift by horizon and signal-readiness state.

This answers whether proprietary live data actually creates value.

### P1 — Expand outcome collection

The immediate bottleneck is not another model architecture but too few live outcomes. Every monitored completed event should receive a verified attendance outcome and source.

### P2 — Multi-club global model

Once sufficient outcomes and trajectories exist across clubs, build a global model with club/opponent/competition/stadium context and use club-specific calibration where justified.

### P2 — Probabilistic calibration

Evaluate calibrated P10/P50/P90 with pinball loss and interval coverage. Avoid presenting wide intervals as high confidence merely because empirical coverage is high.

## 10. Product principle

Beyond's defensibility should be measured as:

**historical baseline + proprietary live signal uplift + reliable uncertainty + decision support**

—not as ownership of a particular regression algorithm.
