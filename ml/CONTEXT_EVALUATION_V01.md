# Beyond Ticketing — Context Snapshot & Ablation v1

Status: **research infrastructure active**  
Production impact on P10/P50/P90: **none**

## Goal

Measure whether context layers improve attendance forecasts without leakage, pseudo-replication or manually forcing the Context Matrix weights into P50.

## Checkpoints

Every monitored event is eligible for immutable snapshots at:
- `T-7d` — 168 hours before kickoff;
- `T-3d` — 72 hours before kickoff;
- `T-24h` — 24 hours before kickoff;
- `T-6h` — 6 hours before kickoff.

`event_context_snapshot_15m` checks due checkpoints every 15 minutes.

## Leakage rule

A context observation may enter a snapshot only when all of the following are at or before the checkpoint:
- `observed_at`;
- `created_at`;
- `source_observed_at` when present.

A forecast may enter the snapshot only when:
- `forecast_generated_at <= checkpoint_at`; and
- its source snapshot, when present, was also captured by the checkpoint.

Once `(ticket_event_id, checkpoint_code)` is inserted, Snapshot v1 does not update it. Later information therefore cannot rewrite an earlier checkpoint.

The bootstrap is marked `retrospective_point_in_time`; future snapshots captured within 30 minutes after the checkpoint are marked `prospective`.

## Frozen data

Each snapshot stores:
- historical baseline P50 and source forecast identity;
- existing engine P50 / correction status when available;
- raw live-ticketing metrics already calculated by Demand Engine;
- latest eligible non-ticketing Context Matrix observation for every active feature;
- explicit `observed`, `unknown`, `blocked_external_access` or `degraded_automation` state;
- source/confidence evidence;
- coverage counts.

Snapshot v1 does not invent a new scarcity transformation. Raw `available_total` is frozen alongside the existing live metrics.

## Ablation variants

Registered sequence:
1. `baseline`;
2. `baseline_ticketing`;
3. `baseline_ticketing_sporting`;
4. `baseline_ticketing_sporting_match`;
5. `baseline_ticketing_sporting_match_hype`.

A variant is evaluated only when an actual P50 prediction exists in `context_ablation_predictions_v1`.

The system automatically creates:
- `baseline` from the historical baseline captured at the checkpoint;
- `baseline_ticketing` only when the existing Demand Engine had a real controlled live blend and `final_p50 != historical_p50`.

No P50 is generated by multiplying Context Matrix weights by a baseline. Missing context variants remain `no_predictions` until a real prediction method exists.

## Fair comparison

For each checkpoint and variant, `dashboard_context_ablation_results_v1` joins:
- immutable snapshot;
- variant P50;
- baseline P50 from the same snapshot;
- verified attendance outcome.

Reported metrics:
- independent event count;
- club count;
- variant MAE;
- baseline MAE on the **same events**;
- `MAE uplift = baseline MAE - variant MAE`;
- variant bias;
- baseline bias on the same events.

Positive MAE uplift means the variant improved absolute error. Comparison never substitutes a larger baseline sample for a smaller variant sample.

Raw context JSON, prediction metadata and source payloads remain unavailable to browser roles. Dashboard access uses limited column grants and RLS-backed `security_invoker` views.

## Promotion

No context layer may modify production P50 solely because its Context Matrix research-prior weight is high. Promotion requires stable out-of-sample improvement on independent events and a documented decision to activate the prediction method.
