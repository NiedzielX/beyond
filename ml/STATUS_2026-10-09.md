### Live feature layer

A canonical `live_features_v1` query is versioned in the repository and a backend-only Supabase RPC `get_live_features_v1(ticket_event_id)` is deployed.

It computes:

- available inventory / first available / available index;
- net removed since first and previous snapshot;
- velocity since previous snapshot;
- matched-sector absorption/release;
- 6h and 24h velocity;
- 6h vs 24h acceleration;
- sectors entering/leaving the public response;
- coverage-change and release flags;
- raw snapshot count.

The query uses the union of current and previous sectors so a disappearing sector is not silently lost. Its semantics explicitly remain `demand_proxy_not_confirmed_sales`.

RPC permissions are backend-only:

- anon: no execute;
- authenticated: no execute;
- service_role: execute.

A `SupabaseLiveFeatureProvider` consumes the RPC server-side. Unspecified quality state defaults to `partial`, never `ready`.

### Historical bridge

A `SupabaseStoredHistoricalForecaster` reuses already persisted historical P10/P50/P90 from the current `beyond-forecast-v0.3` pipeline. This enables a safe shadow migration without inventing a replacement historical model while v1.7 source recovery is incomplete.

This bridge is not a promotion of v0.3 and not a substitute for v1.7. It only lets the new engine architecture observe the current incumbent forecast with full lineage.

### Shadow runner — ACTIVE

- `run_demand_engine_v1_shadow(ticket_event_id)` — writes one shadow observation;
- `run_all_demand_engine_v1_shadow()` — runs eligible future events and deduplicates by latest source snapshot;
- `get_demand_engine_v1_shadow_evaluation()` — compares historical vs final error once actual attendance exists.

Cron is active:

- job: `beyond_demand_engine_v1_shadow_6h`;
