## P9 v1 — frozen representation direction

Canonical implementation:

- `ml/p9_booking_curve_v1.py`;
- `ml/test_p9_booking_curve_v1.py`.

P9 v1 does **not** train a deep sequence model.

It first creates an auditable PIT-safe representation:

`visible public-inventory snapshots -> normalized canonical curve -> historical curve similarity -> robust remaining-pickup distribution`

Canonical hours before kickoff:

`168, 144, 120, 96, 72, 60, 48, 36, 24, 18, 12, 6`

Hard leakage rules:

1. target snapshots after `as_of_at` are ignored;
2. target canonical points later than the cutoff remain missing;
3. interpolation is allowed only between already-visible target snapshots;
4. no target-path extrapolation is performed by the representation layer;
5. the target event cannot be its own historical neighbor;
6. a reference event must be completed by the target `as_of_at`;
7. similarity uses only canonical points observed for the target;
8. historical reference future pickup may be used only because the reference event was already completed before the target cutoff.

Public inventory remains explicitly classified as:

`demand_proxy_not_confirmed_sales`

Initial similarity method:

- weighted L1 distance;
- minimum three overlapping observed canonical points;
- fixed nearest-reference pool size 5;
- pickup summarized by median, Q25 and Q75.

The first learnable P9 attendance challenger is intentionally **not yet opened**. The next P9 step is a completed-event coverage audit of this representation, followed by a separate precommit for the first residual learner if coverage is sufficient.

## P10 v1 — controlled pooling experiment

Canonical implementation:

- `ml/p10_pooled_horizon_global_v1.py`;
- `ml/test_p10_pooled_horizon_global_v1.py`;
- `.github/workflows/p9-p10-mae-roadmap-v4.yml`.

Research question:

> Does one model trained across all five PIT horizons reduce match-balanced OOS MAE versus the same model trained separately per horizon?

This is a direct test of pooling, not an estimator tournament.

### Data

Frozen canonical history:

- 1,530 matches;
- five complete seasons;
- SHA256 `3c6b35142c6bd20a484f2aa758cd41284fd6f4c6db1353b138f81cf321161569`.

The existing Structural Prior feature builder reconstructs:

- 7,650 PIT rows;
- T-30 / T-14 / T-7 / T-3 / T-1.

Historical data are already exposed research evidence. P10 makes no prospective/unseen claim.

### Controlled model

Both arms use the same fixed model:

`HistGradientBoostingRegressor(loss="absolute_error", learning_rate=.05, max_iter=250, max_leaf_nodes=15, min_samples_leaf=10, l2_regularization=1, random_state=42)`

Comparator:

- `local-horizon-hgb-absolute-error-v1` — separate training per horizon.

Challenger:

- `pooled-hgb-absolute-error-v1` — one training set across horizons, with `horizon_days` as a feature.

No hyperparameter search is performed.

### Independence / weighting

Independent unit:

`match_key`

All horizon rows from one match remain on the same side of every fold.

Training weights are normalized so each match contributes total weight `1`, regardless of how many eligible horizon rows it currently has.

### Validation

- expanding season folds;
- first two seasons minimum training history;
- next season as the held-out temporal group;
- three historical forward folds;
- exact fold manifest SHA persisted.

### Primary evaluation

- match-balanced MAE pooled vs local;
- per-horizon MAE;
- fold MAE;
- event/match improvement rate;
- fold improvement rate;
- paired match-block bootstrap;
- 5,000 draws;
- seed 42.

## Governance v2 — precommitted interpretation

Canonical implementation:

- `ml/research_advance_governance_v2.py`;
- `ml/test_research_advance_governance_v2.py`.

Statuses:

### `NO_RESEARCH_GAIN`

No positive MAE point gain or basic stability/evidence-integrity guardrails fail.

### `POINT_GAIN_UNCERTAINTY_LIMITED`

Positive and sufficiently stable point result worth further research, but precision and/or practical business magnitude are not yet strong enough to call robust.

### `ROBUST_RESEARCH_ADVANCE`

Requires all of:

1. positive MAE point gain;
2. event/fold stability;
3. PIT + lineage + reproducibility pass;
4. a predeclared minimum practically meaningful MAE improvement;
5. observed gain at least that large;
6. event-block `ΔMAE` interval entirely below zero by default.

No arbitrary meaningful-improvement threshold is hardcoded.

Until a business-derived threshold exists, new experiments are **not allowed** to return `ROBUST_RESEARCH_ADVANCE`.

This prevents results such as `3012 -> 2998` from being described as robust improvement merely because the point estimate is lower.
