## Research question

> Does PIT live ticket trajectory between 72h and 168h before kickoff reduce event-balanced MAE beyond the Structural Prior T-7 anchor?

This is a new challenger family. It does not mutate frozen final24 or Long72 packages.

## Why the harness is committed before N=9

The ninth event must not be followed by ad-hoc choices made after viewing Long168 model results.

Therefore P7 v1 precommits before the gate opens:

- exact window and sampling contract;
- event/as-of/snapshot freeze procedure;
- target-leakage checks;
- T-7 anchor rule;
- feature allowlist;
- candidate family and fixed parameters;
- forward-event validation protocol;
- primary metric;
- uncertainty method;
- research advancement interpretation;
- production block.

## Gate and freeze order

At `N<9`:

`freeze_manifest(...)` must fail with `P7_NOT_READY`.

At `N>=9`:

1. export `public.export_d2_long_horizon_168_rows_v1()`;
2. filter exact rows with `72 < hours_to_kickoff <= 168`;
3. verify PIT lineage and absence of target/outcome keys;
4. freeze exact `ticket_event_id + requested_as_of_at + requested_snapshot_id + bucket_6h` identities;
5. persist deterministic manifest SHA256;
6. only after the identity manifest exists may attendance labels be joined for P7 evaluation;
7. only then may model comparison run.

The frozen manifest records no actual attendance values and no model results.

## PIT / leakage gates

Every frozen row must satisfy:

- `point_in_time_validated = true`;
- export snapshot id equals feature snapshot id;
- export `requested_as_of_at` equals feature `as_of_at`;
- `requested_as_of_at < kickoff_at`;
- reported hours-to-kickoff agrees with timestamps;
- event x 6h bucket identity is unique;
- target/outcome fields are absent from the freeze payload.

## Anchor contract

For the 72–168h band, the incumbent control is:

**Structural Prior T-7 / zero live correction.**

Rules:

- the T-7 structural forecast must be PIT-safe and available at or before the row as-of time;
- do not interpolate backward from T-3/T-1;
- do not extrapolate frozen Long72 P2 backward beyond 72h;
- P7 v1 learns only a live residual over the T-7 structural anchor.

## Event weighting

Rows are not independent evidence.

During model fitting each event contributes total weight `1`, so an event with more 6h snapshots cannot dominate the fit merely because it has better historical coverage.

Independent evaluation unit remains:

`ticket_event`

## Forward validation

Use canonical:

`ml/temporal_validation_v1.py::build_forward_event_folds`

Contract:

- strict chronological forward-event folds;
- minimum training events: `5`;
- `train_end < test_start`;
- tied kickoffs cannot train one another;
- no random snapshot split;
- exact fold identities and manifest SHA must be persisted.

At N=9 this can create only a small forward evidence set. That limitation must be reported rather than hidden.

## Primary metric

**Event-balanced MAE**

For each held-out event:

1. calculate mean absolute error across its eligible 72–168h rows;
2. average those event MAEs with equal event weight.

Secondary metrics:

- median AE;
- signed bias;
- P90 AE;
- worst-event degradation;
- event-improvement rate;
- forward-fold MAE delta;
- MAE by 24h band: 72–96 / 96–120 / 120–144 / 144–168.

## Uncertainty contract

Use:

`ml/mae_delta_uncertainty_v1.py`

with:

- paired event-block percentile bootstrap;
- 5,000 resamples;
- seed `42`.

Interpretation:

- `ΔMAE >= 0` → `NO_MAE_GAIN`;
- `ΔMAE < 0`, CI crosses zero → `POINT_GAIN_UNCERTAINTY_LIMITED`;
- CI upper bound `<0` → `SUPPORTED_HISTORICAL_FORWARD_GAIN`.

The interval is mandatory evidence, but N=9 is not expected to provide production-grade statistical certainty.

## Research advancement rule

A candidate may advance only as a **research challenger** when all of the following hold:

1. strict-forward event-balanced MAE is below the T-7 anchor;
2. a majority of independently held-out events improve;
3. a majority of usable forward folds improve;
4. PIT, lineage and reproducibility checks pass.

Bootstrap uncertainty and bias/tail diagnostics must be reported with the decision.

A candidate cannot become production-active from P7 v1.
