## Interpretation

The stacked model still confirms substantial complementary live information, but the generic live features used by v4 are insufficient to reliably identify the event regime where the live expert should replace the Structural Prior.

The key diagnostic remains unchanged:

- unconditional v2 live expert: approximately **2,929 MAE**;
- nested v3 gate: approximately **3,054 MAE**, safer but conservative;
- stacked v4: approximately **3,107 MAE**;
- non-deployable oracle prior-vs-live event switch: approximately **1,868 MAE**.

The target ~1,900 is therefore present in the pair of experts; the missing capability is expert selection.

## Missing signal identified for v5

The meta-gates in v4 did **not** use the engineered T-24h ticketing signal already validated in the earlier `Ticketing Challenger v1`:

`hybrid_v6 = matched sector 6h velocity pct-of-first per hour, with raw 6h velocity fallback`

Canonical source:

`public.ticketing_challenger_dataset_v1`

The SQL contract guarantees:

- checkpoint = T-24h;
- feature snapshot timestamp <= checkpoint;
- matched-sector velocity preferred when available;
- raw velocity fallback otherwise.

This makes `hybrid_v6` a point-in-time-safe candidate feature for the next gate.
