## Fixed forecast contract

**Target and unit:** the exact registered `available_total_seats` public availability total from a validated fresh source seal. It is not inventory sold, demand, attendance, or revenue.

**Issue coordinates:** one immutable comparator bundle per new eligible source seal after comparator activation. Both methods share one common coordinate. Record `projection_reference_at` as the actual DB source-read-completion clock, before calculating either value. The age term below uses only this clock; `issued_at` is a separate actual DB clock stamped after both numeric values are calculated, and `target_at = issued_at + h` for h in exactly `{24,48,72}`. Never substitute `known_at`, `captured_at`, a cron minute, or a later export time for either clock. Persist `projection_reference_at`, `issued_at`, and their measured latency. Require `0 <= issued_at - projection_reference_at <= 90 seconds` (the frozen B runtime bound); otherwise refuse the paired issue and retain the opportunity/refusal. This intentionally differs from B’s formula clock: slope projection uses read completion because the actual issue clock cannot exist before both calculations, while target coordinates remain the actual issued_at+h. Do not claim these clocks are identical. Reuse source seals only when their actual `known_at` is no later than calculation start and their capture/read/hash bindings validate. Issue each source seal at most once. Targets at or after registered kickoff are stored `OUTSIDE_KICKOFF`, prediction null, and separately counted.

**PERS control:** `PERS_h = origin.available_total` for each pre-kickoff horizon; preserve numeric zero. This is the comparator’s control value at the common coordinate, not a new or modified row in the existing PERS lane.

**Fixed drift24 recipe:** use the frozen B/LAD drift24 anchor-and-propagation recipe, without fitting or selecting parameters:

1. From this same event’s validated source-lane seals already known by calculation start, choose the latest valid anchor with `origin.captured_at - 30h <= anchor.captured_at <= origin.captured_at - 24h`; tie-break by highest seal ID. Preserve the B/LAD break rule: an invalid source, source-family/source change, or sector-count change starts a new segment; do not use an anchor at or before the latest break. Both origin and anchor must have the same registered identity, source family and unit, plus an identical sorted sector/price-area ID set. An intervening `MISSING_SOURCE`, `SKIPPED_STALE`, `INVALID_SOURCE`, or `INTERNAL_ERROR` attempt known by calculation start breaks drift support until a later compatible anchor exists. These checks affect drift support only; they never discard a valid PERS issue.
2. Let `elapsed_hours = (origin.captured_at - anchor.captured_at)` in elapsed hours and `slope24 = (origin.available_total - anchor.available_total) / elapsed_hours`. Let `age_hours = (projection_reference_at - origin.captured_at)` in elapsed hours. For horizon h, `DRIFT24_h = greatest(0, origin.available_total + slope24 * (h + age_hours))`. The issue latency is reported because the formula’s reference projection precedes the `issued_at+h` target by that measured interval; do not silently fold latency into the frozen slope formula. Use float8 semantics from the pinned reference, with no rounding or upper-capacity clamp.
3. When a valid current PERS source exists but the anchor/support checks fail, the whole drift24 policy returns the numeric PERS value and records `FALLBACK_PERS` plus a fixed reason (`NO_24H_ANCHOR`, `SOURCE_BREAK`, or `SCOPE_MISMATCH`). If the current source itself is invalid, both methods are unavailable; do not label that as fallback. Keep learned-only drift support as a diagnostic; it is not the primary result. First-point/short-history issues still produce all three PERS forecasts and three paired fallback values.

## Outcomes, pairing and reporting

- Use P0-4c’s exact latest-observation/no-backtracking selection order. At the real score watermark, choose the newest attempt per snapshot by `known_at DESC, attempt_id DESC`, then choose the newest post-issue captured snapshot (`captured_at > issued_at`, `captured_at <= target_at`, `known_at <= watermark`) before validating it. If that selected latest observation is non-READY/invalid/stale, refuse it; never fall back to an older READY snapshot. A newer post-issue `INTERNAL_ERROR` with unknown capture time that is later than the last trustworthy observation yields `SOURCE_ORDER_UNKNOWN`, not an older label. Accept the selected target only if `target_at - captured_at` is in `[0,6h]`, identity/family/unit and source/seal/hash bindings validate, and its actual knowledge clock is no later than the watermark. Use that one exact target snapshot ID/value for both PERS and drift24. Pool/sector changes with valid registered identity/family/unit remain scored with explicit scope flags; they are not silently dropped. Missing, stale, invalid, unknown-order, and outside-kickoff outcomes remain separate statuses, never numeric zero.
- Keep pool/sector scope flags on origin, anchor and target: source status, transition/gap, sector-count delta, membership delta, and stable ID-set comparison. Include source-comparable scope changes in the availability outcome with flags; report a preregistered stable-scope sensitivity separately. Never interpret a count change as sales. Price, promotion, advertising and pool policy are `UNKNOWN` unless contemporaneous evidence says otherwise.
- For every horizon, report all source-eligible pre-kickoff opportunities, actual attempts, refusals/unattempted, PERS numeric forecasts, drift READY/fallback/outside/unavailable counts, future/due/matured targets and accepted labels. `forecast_coverage = numeric full-policy forecasts / valid pre-kickoff opportunities`; `scoring_coverage = accepted common labels / matured eligible targets`. Preserve missingness and late-start gaps. A missing value is not zero.
- Primary comparison is **full-policy drift24 including PERS fallback versus PERS**. For an identical event×issue×horizon×target-seal set, compute per-event MAE then event-balanced MAE, plus signed bias, P90 and worst-event MAE by horizon. Delta is `drift24 - PERS`; negative is better. Learned-only drift MAE and coverage are secondary diagnostics and cannot select the winner.
- Primary horizon is +72h; +24/+48 are guardrails. Precommitted support criterion: once at least 30 new independent fixtures across 8 clubs have eligible paired outcomes, full-policy +72 event-balanced MAE must be at least 10% below PERS and its paired event bootstrap 95% interval (10,000 draws, seed42) for delta must be entirely below zero; +24 and +48 point MAEs must not exceed PERS. Otherwise report `NOT_SUPPORTED`, `PARTIAL`, or `UNKNOWN` as applicable; the 30/8 minimum is a review floor, not automatic PASS. Report all three horizons regardless of result. Do not select a version per horizon or change the criterion after labels appear.
- This is availability-only research. It makes no terminal-attendance MAE/1200-seat, demand, causal intervention, or commercial revenue claim. E5, the old B cohort and this new comparator are separate cohorts and never pooled.
