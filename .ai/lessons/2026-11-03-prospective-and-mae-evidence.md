# Prospective evidence and cloud execution

- A future daily inventory path is a different product output from successive revisions of final attendance. Raw inventory is neither paid sales nor stadium attendance. Keep targets, units, charts and MAEs separate.
- One event with many horizons remains one independent event. Compute event means first; for contributions allocate each event's unit weight across its available horizons. Use a common event cohort to compare horizons.
- Frozen season splits can be replayed for diagnostic decomposition, but their previously exposed outcomes are not fresh validation. Fit temporary fold copies only; never use an all-season fitted artifact to claim holdout error on its training events.
- Preserve genuine missed windows. An immutable failed-input attempt can be a correct fail-closed execution, not a successful prediction. No scores means unknown MAE, not MAE=0.
- Source JSON/YAML, a passing workflow and persisted DB evidence are three different levels. Prepared SQL and OIDC code are not deployed automation. A bounded cloud watcher depends on the host surviving and is not autonomous coding after the session closes.
- A private immutable Storage backup was verified by byte-level readback and restored ledger counts. Do not put private source exports or the service-role credential in a public repository.
- Local npm HTTP403 does not prove the panel cannot build. GitHub Actions run41709931291 passed actual TypeScript and production build after an explicit parser return-type correction. Hosted build evidence is not interactive browser/E2E evidence.
- Newer remote main added canonical MAE v6 while the cloud snapshot still had v5. Preserve the newer plan and its commit ancestry when reconciling branches.
